# Spending history is kept as minimal payments in SQLite, replaced window by window

Banks serve only 3–13 months of transactions, so Yiji has to keep history itself. To store as little private data as possible, the bank profile maps each Enable Banking transaction to a `Payment`: name (first remittance line), payee (creditor), amount, currency, booking date and payment method. It drops everything else: credits, pending, cancelled and rejected transactions, and all other fields. The payments live in `yiji.sqlite3`, using stdlib `sqlite3` with WAL mode, because the dashboard and the daily sync may write at the same time. That rules out the atomic-rewrite JSON files used for small state, and needs no new dependency.

Banks often send no stable transaction id, so payments aren't matched one by one. Each fetch replaces the account's payments from the first day the bank served onwards. Rows before that day stay. Accounts are keyed by Enable Banking's `identification_hash`, which stays the same across sessions, so reconnecting doesn't duplicate the overlap. The cost: if a bank answers a window but leaves out a payment it had served before, that payment is dropped, because Yiji trusts the bank's latest view of the days it served.
