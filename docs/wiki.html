Yiji

Bank connection flow

sequenceDiagram
  participant U as Browser
  participant Y as Yiji (local)
  participant EB as Enable Banking
  participant GP as yiji-site callback.html
  U->>Y: click "Connect bank"
  Y->>EB: POST /auth (state = "port.nonce", redirect = active redirect URL)
  EB-->>U: redirect to bank (Mock ASPSP in sandbox)
  alt sandbox
    U->>Y: GET https://localhost:8100/callback?code&state
  else production
    U->>GP: bank returns ?code&state (https required)
    GP->>Y: GET /api/bank/callback (port from state, loopback only)
  end
  Y->>Y: check nonce (single use)
  Y->>EB: POST /sessions {code}
  Y-->>U: 303 → / (or /?bank_error=code)
  U->>Y: GET /?period=week|month[&counterparty=name | &category=id]
  Y->>EB: GET /accounts/{uid}/transactions (last 30 days, cached 6 h)
  Y-->>U: KPI total + "Spending per day" bar chart
  Y-->>U: Counterparties + Categories donuts
  U->>Y: ⚙ Settings (header) → Categories · Counterparties boxes

Spending = debits (DBIT) excluding cancelled/rejected, by booking → value → transaction date, in the currency with most spending. Periods are rolling 7 / 30 days ending today.

main currency] --> PF["profile_for(ASPSP name, country)"]

  • Counterparties donut: who was paid, so recurring charges (subscriptions, rent) show what eats the most money. A nameless payment goes by its payment method: ATM withdrawal, Card payment, BLIK, Transfer, Direct debit, Fee, Other. Add a bank = one file in app/bank_profiles/ + an entry in its registry (see docs/adr/0001).
  • Categories are user-created (seeded from YIJI_STARTER_CATEGORIES on first run); deleting one makes its names Uncategorised. A category gets a palette colour when first used and keeps it.
  • Donuts show at most 7 slices: Counterparties = 6 biggest + hatched "Other"; Categories = 6 biggest + hatched "Other" + grey "Uncategorised". Terms: GLOSSARY.md.

  • Counterparty matching uses the Counterparties donut's names (case-insensitive, nameless → payment method); category matching uses the category rules. The donuts ignore the filter.
  • Total label: "Spent on <name>, last month". Nothing in range → "No spending in this period." with the filter kept.
  • Logic: app/spending_filter.py (pure). UI: SpendingFilters + SpendingOverview, both updated in place.

Request flow: opening the dashboard

sequenceDiagram
  Browser->>FastAPI: GET /
  FastAPI->>NiceGUI: @ui.page("/") dashboard_page
  NiceGUI->>NiceGUI: not configured → alert · not connected → empty_state + Connect · connected → period_filter, SpendingFilters, SpendingOverview, Donut ×2 + ⚙ SettingsDialog (CategoryList + CounterpartiesTable) · category edits update Donut, filters, overview, list and table in place (no re-render, no scroll jump)
  NiceGUI->>NiceGUI: session ended → stored session cleared, "expired" alert + Connect · other bank error → "unavailable" alert, session kept
  NiceGUI-->>Browser: HTML + websocket for live updates

"Session ended" = the bank error body's error contains SESSION: EXPIRED_SESSION, CLOSED_SESSION, REVOKED_SESSION, SESSION_DOES_NOT_EXIST (also WRONG_SESSION_STATUS). The HTTP status alone never ends a session.

Usage

uv sync                                   # install
uv run playwright install chromium        # once, for E2E
uv run python -m app.tls                  # once: print YIJI_SSL_* lines, add them to .env
uv run python -m app                      # run → https://localhost:8100 (sandbox)
uv run ruff check . && uv run ruff format --check .
uv run pyright
uv run pytest                             # unit
uv run pytest -m e2e                      # E2E (fake Enable Banking)
uv run pytest -m sandbox                  # live: real sandbox app from .env

Tests only ever use the sandbox app; set YIJI_ENABLE_BANKING_ENVIRONMENT=production only for the real site.

One-time setup

  1. Create the public repo SovernDK/yiji-site (this repo is private, so it can't use Pages); Settings → Pages → Deploy from branch main / root.
  2. Publish site/ there: scripts/publish-site.sh (re-run after editing site/).
  3. Enable Banking control panel: sandbox redirect https://localhost:8100/callback; production redirect https://sovernDK.github.io/yiji-site/callback.html; privacy/terms URLs …/privacy.html and …/terms.html.
  4. Sandbox: uv run python -m app.tls, copy the printed lines to .env; accept the self-signed certificate warning once in the browser. python -m app refuses to start if the port or certificate doesn't match the redirect URL.
  5. Production: set your bank in YIJI_ENABLE_BANKING_ASPSP_NAME / _COUNTRY.
