Bank connection flow

sequenceDiagram
  participant U as Browser
  participant Y as Yiji (local or server)
  participant EB as Enable Banking
  participant GP as yiji-site callback.html
  U->>Y: click "Connect bank"
  Y->>EB: POST /auth (state = "target.nonce", redirect = active redirect URL)
  EB-->>U: redirect to bank (Mock ASPSP in sandbox)
  alt sandbox
    U->>Y: GET https://localhost:8100/callback?code&state
  else production
    U->>GP: bank returns ?code&state (https required)
    GP->>Y: GET /api/bank/callback (target: port → http://127.0.0.1:port · base64url https origin → that origin)
  end
  Y->>Y: check nonce (single use)
  Y->>EB: POST /sessions {code}
  Y-->>U: 303 → / (or /?bank_error=code)
  U->>Y: GET /?period=week|month[&counterparty=name | &category=id]&compare=m2m|y2y[¤cy=XXX]
  Y->>EB: GET /accounts/{uid}/transactions (first sync: 13 months, refused → 90 → 30 days · later: from last sync − 7 days · at most every 12 h)
  Y->>Y: drop transfers to a connected account (IBAN hash) → bank profile → booked debits only → replace that window in yiji.sqlite3
  Y->>Y: fetch missing ECB rates · convert to chosen currency
  Y-->>U: KPI total + "Spending per day" bar chart
  Y-->>U: Counterparties + Categories donuts
  U->>Y: ⚙ Settings (header) → Categories · Counterparties boxes

State target and its limits: docs/adr/0004. On connect, Yiji keeps SHA-256 hashes of the connected accounts' IBANs in bank.json (never the IBANs) so money moved between them is not spending. Enable Banking refusals are logged as Enable Banking refused POST: 400 REDIRECT_URI_NOT_ALLOWED (no path, so no account ids); the dashboard shows only a safe message.

Spending = booked debits only (pending, cancelled, rejected and income are never stored), dated by booking (else value) date, shown in the chosen currency (default: the one with most spending). Periods are rolling 7 / 30 days ending today. Comparison: the same number of days ending one month (M2M) or one year (Y2Y) earlier, a missing day in a shorter month becomes its last day; days the bank gave no history for count as 0.

  • Counterparties donut: who was paid, so recurring charges (subscriptions, rent) show what eats the most money. A nameless payment goes by its payment method: ATM withdrawal, Card payment, BLIK, Transfer, Direct debit, Fee, Other. Add a bank = one file in app/bank_profiles/ + an entry in its registry (see docs/adr/0001).
  • Categories are user-created (seeded from YIJI_STARTER_CATEGORIES on first run); deleting one makes its names Uncategorised. A category gets a palette colour when first used and keeps it.
  • Donuts show at most 7 slices: Counterparties = 6 biggest + hatched "Other"; Categories = 6 biggest + hatched "Other" + grey "Uncategorised". Terms: GLOSSARY.md.

AI categories

sequenceDiagram
  participant T as Daily sync / ⚙ "Categorise with AI"
  participant A as AutoCategoriser
  participant C as categories.json
  participant O as Ollama (YIJI_AI_CATEGORY_MODEL)
  T->>A: run(stored payments)
  A->>C: load: names with no rule, user's own rules
  loop batches of YIJI_AI_CATEGORY_BATCH_SIZE names
    A->>O: POST /api/chat · categories, examples (user's rules), id + name + ≤3 titles + method per counterparty
    O-->>A: {"1": "Groceries", "2": null} (a ```json fence is accepted)
    A->>C: update (load → assign_suggested → save): only names still without a rule, marked AI
  end
  A-->>T: count assigned
  • On only with a key: OLLAMA_API_KEY (ollama.com/settings/keys). No local Ollama app needed; without a key Settings shows how to enable it.
  • User wins: AI never overwrites a rule; rows it chose show an AI badge; picking a category by hand removes the badge and makes the rule the user's (it then serves as an example).
  • Safe answers: the model answers by id because it copies long company names inexactly; Ollama Cloud ignores the format schema, so the prompt spells out the shape. Ids not asked about and categories not in the list are dropped; null = left Uncategorised. Each batch is saved as answered, so an outage keeps earlier batches.
  • Failures: sync logs Categories not assigned: … and keeps its exit code; the button shows "AI is unavailable right now".
  • Sent to Ollama: counterparty names, up to YIJI_AI_CATEGORY_TITLES_PER_NAME payment titles, payment method, category names. Never amounts, dates or account ids.
  • Concurrent writes: the dashboard and the sync both change categories through CategoryStore.update, which starts from the file, so neither overwrites the other.

Spending history, exchange rates, daily sync

flowchart LR
  EB[(Enable Banking
transactions JSON)] --> PF["profile_for(ASPSP name, country)"]
  PF -->|Mock ASPSP / FI| MA[mock_aspsp]
  PF -->|Bank Pekao / PL| PK["pekao
method from last description line"]
  PK --> PAY

name · payee · amount · currency · booked_on · payment method"]
  GE --> PAY
  PF -.->|"credit, pending, cancelled,
rejected, undated, 0 → dropped"| X((✕))
  PAY -->|"replace_from(account key, served from)"| DB[(payments
yiji.sqlite3)]
  FR[(Frankfurter / ECB)] -->|only missing days| RT[(exchange_rates
per euro, per day)]
  DB --> CV["convert_payments(currency)
rate on booking day, else latest ≤ 7 days before"]
  RT --> CV
  CV --> UI((Dashboard))
  CV -.->|no rate| W["left out
warning only when in the shown days"]
  • Pekao: no ISO codes; the last remittance line is the operation type. Card: TRANSAKCJA KARTĄ PŁATNICZĄ · BLIK: PŁATNOŚĆ BLIK, PRZELEW BLIK WYCHODZĄCY · Transfer: PRZELEW, PRZELEW MOBILE, REALIZACJA PŁATNOŚCI PEOPAY · Fee: PROWIZJE AUT., POBRANIE ZALEGŁEJ OPŁATY. Anything else → Other + a log warning naming the type (add it to app/bank_profiles/pekao.py). BLIK REF … lines are not kept as names.
  • Stored per payment: first remittance line (name), creditor (payee), amount, currency, booking date, derived payment method, and the account's Enable Banking identification_hash (stable across sessions). Nothing else from the bank reaches disk.
  • No duplicates without ids: each fetch replaces that account's rows from the day the bank served onwards; older rows stay after the bank stops serving them. Reconnecting keeps the history.
  • Bank connection gone: the dashboard keeps showing stored history with the alert and Connect button above it.
  • Rates: ECB reference rates (EUR base, cross rates through EUR). Earlier days are fetched once; today is re-checked after the refresh window. A rates outage shows a warning and keeps older rates.
  • Choose currency: toggle next to Compare (YIJI_DISPLAY_CURRENCIES + any currency in the history); choice in ?currency= (left out for the default); changing it reloads the page.
  • Default currency: main_currency values each currency's spending in euros at its payment days' rates; if any payment has no rate, the currency with most payments wins (bigger amount breaks a tie).
  • Comparison across rates: each period uses its own days' rates, so in a converted view the % change includes exchange-rate moves. A muted note under the total says so only when a converted payment falls in the shown days (KpiTile note, total-note).
  • Shown days: the selected period and its comparison window, narrowed by the counterparty/category filter (booked_within). The "left out" warning (rates-error, under the filters) and the note both follow them and update in place on every period, comparison or filter change.

Daily sync and backup

uv run python -m app.sync     # exit 0 synced · 1 bank/rates error or not configured · 2 reconnect needed; then AI categories if OLLAMA_API_KEY is set
uv run python -m app.backup   # yiji.sqlite3 (SQLite backup API) + categories.json → YIJI_BACKUP_DIR/yiji-YYYY-MM-DD, keeps YIJI_BACKUP_KEEP

On the server both run from deploy/systemd/yiji-sync.service (see Server). Timer: every day at 00:00, Persistent=true catches up a run missed while the server was off. Each sync fetches from the last sync − YIJI_SYNC_OVERLAP_DAYS. The backup runs even when the sync fails; the unit keeps the sync's exit code.

Request flow: opening the dashboard

sequenceDiagram
  Browser->>FastAPI: GET /
  FastAPI->>NiceGUI: @ui.page("/") dashboard_page
  NiceGUI->>NiceGUI: not configured → alert · not connected, no history → empty_state + Connect · not connected with history → Connect + history · otherwise → period_filter, comparison_filter, currency_filter, SpendingFilters, SpendingOverview, Donut ×2 + ⚙ SettingsDialog (CategoryList + CounterpartiesTable) · category edits update Donut, filters, overview, list and table in place (no re-render, no scroll jump)
  NiceGUI->>NiceGUI: connected, consent ends within YIJI_RECONNECT_WARNING_DAYS → "ends in N days" / "ends today" notice + Reconnect (count updated hourly in place)
  NiceGUI->>NiceGUI: session ended → stored session cleared, "expired" alert + Connect · other bank error → "unavailable" alert, session kept · both still show stored history
  NiceGUI-->>Browser: HTML + websocket for live updates

"Session ended" = the bank error body's error contains SESSION: EXPIRED_SESSION, CLOSED_SESSION, REVOKED_SESSION, SESSION_DOES_NOT_EXIST (also WRONG_SESSION_STATUS). The HTTP status alone never ends a session.

Usage

uv sync                                   # install
uv run playwright install chromium        # once, for E2E
uv run python -m app.tls                  # once: print YIJI_SSL_* lines, add them to .env
uv run python -m app                      # run → https://localhost:8100 (sandbox)
uv run ruff check . && uv run ruff format --check .
uv run pyright
uv run pytest                             # unit
uv run pytest -m e2e                      # E2E (fake Enable Banking)
uv run pytest -m sandbox                  # live: real sandbox app from .env

Tests only ever use the sandbox app; set YIJI_ENABLE_BANKING_ENVIRONMENT=production only for the real site.

One-time setup

  1. Create the public repo SovernDK/yiji-site (this repo is private, so it can't use Pages); Settings → Pages → Deploy from branch main / root.
  2. Publish site/ there: scripts/publish-site.sh (re-run after editing site/).
  3. Enable Banking control panel: sandbox redirect https://localhost:8100/callback; production redirect https://sovernDK.github.io/yiji-site/callback.html; privacy/terms URLs …/privacy.html and …/terms.html.
  4. Sandbox: uv run python -m app.tls, copy the printed lines to .env; accept the self-signed certificate warning once in the browser. python -m app refuses to start if the port or certificate doesn't match the redirect URL.
  5. Production: set your bank in YIJI_ENABLE_BANKING_ASPSP_NAME / _COUNTRY.

  3. Key: cp key.pem ~/yiji/secrets/enable-banking.pem && chmod 400 ~/yiji/secrets/enable-banking.pem. The container runs as uid 1000: if id -u prints 1000 that's all; otherwise sudo chown -R 1000:1000 ~/yiji/secrets ~/yiji/backups.
  4. Caddy (~/caddy/Caddyfile, host network) — append, then docker exec caddy caddy reload --config /etc/caddy/Caddyfile: 
    yiji.home.net {
    import itls
    reverse_proxy 127.0.0.1:8100
}
  5. Pi-hole local DNS: add 192.168.33.24 yiji.home.net (Settings → Local DNS Records, or pihole-FTL --config dns.hosts). Without it, home.net resolves to the public internet.
  6. cd ~/yiji && docker compose pull && docker compose up -d; open https://yiji.home.net → Connect bank → select all accounts. The first fill stores the 90 days Pekao serves.
  7. Daily sync + backup: sudo cp deploy/systemd/yiji-sync.* /etc/systemd/system/ && sudo systemctl daemon-reload && sudo systemctl enable --now yiji-sync.timer; logs: journalctl -u yiji-sync.
  8. Update: cd ~/yiji && docker compose pull && docker compose up -d.

The bank callback reaches the server through the GitHub Pages relay: the redirect URL registered in Enable Banking stays the Pages one, and YIJI_PUBLIC_URL puts the server's origin into state. A new image or server never needs the Enable Banking panel changed.
